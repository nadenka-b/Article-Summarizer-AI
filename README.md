# Article-Summarizer-AI — мультиагентная платформа суммаризации научных статей

## Описание
Article-Summarizer-AI — это интеллектуальная система для автоматического анализа и суммаризации научных публикаций. Пользователь может загрузить статью в формате PDF или указать её идентификатор (например, arXiv ID). Система извлекает текст, очищает его от артефактов и генерирует краткое (abstract-like) или развернутое (по секциям) резюме с сохранением ключевой методологии, фактов и выводов.

Проект построен на базе мультиагентной архитектуры (Extractor, Summarizer, Validator, Critic, Editor), использует гибридный поиск по базе научных знаний (BM25 + Qdrant) для извлечения few-shot примеров и концептов, а также включает контур Human-in-the-Loop (HITL) для экспертной модерации и активного обучения системы.

## Цель проекта
Автоматизировать процесс аннотирования и реферирования сложных научных документов с качеством, близким к экспертному, за счёт:
- Иерархической суммаризации длинных текстов с разделением по секциям (Introduction, Methods, Results, Conclusion);
- Использования базы знаний (RAG) для валидации терминологии и подбора релевантных шаблонов аннотирования;
- Мультиагентной верификации (LLM-as-a-Judge) на предмет фактической точности, полноты и соблюдения научного стиля;
- Накопления эталонных пар «статья → резюме» через интерфейс обратной связи от экспертов-редакторов.

## Стек технологий
- **Backend:** FastAPI, SQLAlchemy (async), Celery, Redis
- **LLM / Движки:** Ollama (qwen2.5), HuggingFace Transformers (Qwen, модели NLLB)
- **RAG & Векторный поиск:** Rank-BM25 (лексический поиск) + Qdrant (семантический поиск) + RRF-фьюжн
- **Эмбеддинги:** sentence-transformers (paraphrase-multilingual-MiniLM-L12-v2)
- **Парсинг и обработка текста:** pdfplumber / PyMuPDF (или интеграция с GROBID), NLTK
- **БД:** PostgreSQL, SQLite (для локального тестирования)
- **Инфраструктура:** Docker, Docker Compose, Nginx
- **Оценка качества (Метрики):** sacrebleu (BLEU, ChrF++), METEOR, ROUGE-1/2/L, BERTScore, Coverage Score
- **Тестирование:** pytest, pytest-asyncio, pytest-cov, pytest-mock
- **Python:** 3.12

## Архитектура агентов
В системе реализован конвейер из 5 специализированных агентов:
1. **Extractor** — извлекает сырой текст из PDF/API, очищает его от мусора и производит чанкинг (структурирование по секциям).
2. **Summarizer** — генерирует первичные саммари (посекционно или агрегированно).
3. **Validator** — проверяет жесткие лимиты (длина, формат), контролирует наличие ключевых терминов и отслеживает плагиат (дословный копипаст предложений).
4. **Critic** — выступает в роли судьи (LLM-as-a-Judge), оценивая связность, научный стиль, полноту раскрытия методов/результатов и отсутствие галлюцинаций.
5. **Editor** — принимает правки от Критика и Валидатора, переформулирует неудачные выражения, обогащает текст упущенными деталями и выдает финальный вариант.

## Контур Human-in-the-Loop (HITL)
Если финальный вариант резюме получает низкий балл от агента-критика (например, за фактическую точность) или отклоняется агентом-валидатором, задача не отдается пользователю, а перенаправляется в очередь модерации.
Эксперт-редактор через веб-интерфейс вносит финальные правки. Подтвержденный человеком результат сохраняется в PostgreSQL и дублируется в векторную базу знаний Qdrant в качестве нового few-shot примера для улучшения последующих генераций.
